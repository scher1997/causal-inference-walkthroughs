  • Judge the propensity model by balance, not prediction accuracy. Standardized mean differences under about 0.1 is the usual rule of thumb, shown in a love plot.

The chapter compares regression adjustment, IPW, matching, and AIPW. AIPW is doubly robust: it is consistent if either the outcome model or the propensity model is right. Cross-fitting AIPW with flexible ML models gives the double/debiased ML recipe.

The treated units have larger effects here, so the ATT exceeds the ATE. Choose the estimand from the business question. Sensitivity tools such as E-values or sensemakr ask how strong a hidden confounder would need to be to explain the result away.

Setting: observational data — nobody randomized treatment. Example: customers who chose to enroll in a loyalty program; we want the program’s effect on spend. Enrollees differ systematically (more engaged, higher income), so a naive comparison mixes the program effect with selection.

Propensity score: \(e(x) = P(T=1 \mid X=x)\). Rosenbaum and Rubin (1983): if treatment is as-good-as-random given \(X\), it is also as-good-as-random given the scalar \(e(X)\). So we can balance many confounders through one number.

Rosenbaum, Paul R., and Donald B. Rubin. 1983. “The Central Role of the Propensity Score in Observational Studies for Causal Effects.” Biometrika.
ImportantAssumptions
  1. Unconfoundedness: all common causes of treatment and outcome are in \(X\). Untestable — it rests on domain knowledge.
  2. Overlap (positivity): \(0 < e(x) < 1\) — every type of unit could have been treated or not. Checkable.
  3. No interference, and \(X\) measured before treatment (never condition on post-treatment variables).
NoteEstimators compared

(simulated data; true ATE = 1.0, true ATT > 1 because effects are larger for high-\(x_1\) units, who are also more likely to be treated): naive difference · regression adjustment · IPW (ATE, ATT) · propensity matching (ATT) · AIPW (doubly robust) · cross-fitted AIPW with ML nuisance models.

5.1 Estimate the propensity score and check overlap

Overlap is the first thing to look at. Regions where one group has (almost) no counterparts are where every estimator extrapolates — IPW weights explode there. Common remedies: trim to a region of common support [e.g. 0.05 < e < 0.95; Crump et al. (2009)], or switch the estimand (ATT, or overlap weights).

Crump, Richard K., V. Joseph Hotz, Guido W. Imbens, and Oscar A. Mitnik. 2009. “Dealing with Limited Overlap in Estimation of Average Treatment Effects.” Biometrika.

ps = ps_lib.fit_propensity(X, t)

5.2 Balance diagnostics (love plot)

The goal of a propensity model is balance, not prediction accuracy — judge it by standardized mean differences (SMD1) after weighting/matching, not by AUC. |SMD| < 0.1 is the usual rule of thumb. Check the covariates and relevant transformations (squares, interactions).

1 SMD: standardized mean difference, the difference in group means divided by the pooled standard deviation.

5.3 Estimate the effect several ways

  • Regression adjustment: model \(E[Y|X,T]\) and average predicted differences. Relies entirely on the outcome model.
  • IPW: reweight so the treated and control groups each look like the target population. Relies entirely on the propensity model; variance blows up with extreme weights.
  • Matching (ATT): pair each treated unit with the control closest in (logit) propensity, within a caliper.
  • AIPW: combines both models; consistent if either is right, and efficient if both are. With cross-fitting it pairs naturally with flexible ML learners (the double/debiased ML recipe).

Bootstrap SEs for IPW and matching; AIPW gets an analytic influence-function SE.

Code 
from sklearn.ensemble import GradientBoostingClassifier, GradientBoostingRegressor
from sklearn.linear_model import LinearRegression

def regression_adjustment(Xd, yd, td):
    m1 = LinearRegression().fit(Xd[td == 1], yd[td == 1])
    m0 = LinearRegression().fit(Xd[td == 0], yd[td == 0])
    return float(np.mean(m1.predict(Xd) - m0.predict(Xd)))

def bootstrap_se(fn, n_boot=200, seed=0):
    rng = np.random.default_rng(seed)
    draws = []
    for _ in range(n_boot):
        i = rng.integers(0, len(df), len(df))
        Xb, yb, tb = X.iloc[i].reset_index(drop=True), y.iloc[i].reset_index(drop=True), t.iloc[i].reset_index(drop=True)
        draws.append(fn(Xb, yb, tb))
    return float(np.std(draws, ddof=1))

ipw_ate = lambda Xd, yd, td: ps_lib.ipw(yd, td, ps_lib.fit_propensity(Xd, td), "ATE").estimate
ipw_att = lambda Xd, yd, td: ps_lib.ipw(yd, td, ps_lib.fit_propensity(Xd, td), "ATT").estimate
match = lambda Xd, yd, td: ps_lib.match_att(yd, td, ps_lib.fit_propensity(Xd, td), caliper=0.05)[0].estimate

m1 = LinearRegression().fit(X[t == 1], y[t == 1]); m0 = LinearRegression().fit(X[t == 0], y[t == 0])
aipw = ps_lib.aipw(y, t, ps, m0.predict(X), m1.predict(X))
cf_ml = ps_lib.cross_fit_aipw(df[COVARIATES], y, t,
                              outcome_model=GradientBoostingRegressor(max_depth=3, n_estimators=200),
                              ps_model=GradientBoostingClassifier(max_depth=2, n_estimators=150))

match_est, matches = ps_lib.match_att(y, t, ps, caliper=0.05)
results = pd.DataFrame([
    {"method": "naive difference", "estimand": "-", "estimate": naive, "se": np.nan},
    {"method": "regression adjustment", "estimand": "ATE", "estimate": regression_adjustment(X, y, t), "se": bootstrap_se(regression_adjustment)},
    {"method": "IPW (Hajek)", "estimand": "ATE", "estimate": ipw_ate(X, y, t), "se": bootstrap_se(ipw_ate)},
    {"method": "IPW (Hajek)", "estimand": "ATT", "estimate": ipw_att(X, y, t), "se": bootstrap_se(ipw_att)},
    {"method": match_est.name, "estimand": "ATT", "estimate": match_est.estimate, "se": bootstrap_se(match, n_boot=100)},
    {"method": "AIPW (linear outcome, logit PS)", "estimand": "ATE", "estimate": aipw.estimate, "se": aipw.se},
    {"method": "cross-fit AIPW (gradient boosting, raw X)", "estimand": "ATE", "estimate": cf_ml.estimate, "se": cf_ml.se},
])
results["truth"] = results.estimand.map({"ATE": TRUE_ATE, "ATT": TRUE_ATT})

5.4 Double robustness in action

Deliberately break one model at a time. IPW depends only on the propensity model, regression adjustment only on the outcome model — AIPW survives as long as one of them is right.

Code 
X_bad = X.drop(columns="x1")   # omits x1, the strongest confounder (drives both T and Y)
X_good = X

def aipw_with(X_ps, X_out):
    p = ps_lib.fit_propensity(X_ps, t)
    a1 = LinearRegression().fit(X_out[t == 1], y[t == 1]); a0 = LinearRegression().fit(X_out[t == 0], y[t == 0])
    return ps_lib.aipw(y, t, p, a0.predict(X_out), a1.predict(X_out)).estimate

pd.DataFrame([
    {"propensity model": "correct", "outcome model": "correct", "IPW": ipw_ate(X_good, y, t), "reg. adj.": regression_adjustment(X_good, y, t), "AIPW": aipw_with(X_good, X_good)},
    {"propensity model": "correct", "outcome model": "wrong", "IPW": ipw_ate(X_good, y, t), "reg. adj.": regression_adjustment(X_bad, y, t), "AIPW": aipw_with(X_good, X_bad)},
    {"propensity model": "wrong", "outcome model": "correct", "IPW": ipw_ate(X_bad, y, t), "reg. adj.": regression_adjustment(X_good, y, t), "AIPW": aipw_with(X_bad, X_good)},
    {"propensity model": "wrong", "outcome model": "wrong", "IPW": ipw_ate(X_bad, y, t), "reg. adj.": regression_adjustment(X_bad, y, t), "AIPW": aipw_with(X_bad, X_bad)},
]).assign(truth=TRUE_ATE)

In Table 5.2, leaving the key confounder out of the propensity model breaks IPW but not AIPW (the outcome model rescues it); leaving it out of the outcome model breaks regression adjustment but not AIPW (the weights rescue it). Only when both are wrong does AIPW fail — double robustness is protection against one mistake, not two, and no model fixes a confounder you never measured.

5.5 Practical notes

  • Design before analysis: write down the causal graph; include pre-treatment confounders, exclude mediators and colliders (and instruments, which inflate variance and can amplify bias).
  • Overlap first, then balance, then estimate. Report how many units were trimmed or unmatched — it changes the population the estimate describes.
  • Sensitivity analysis for unmeasured confounding: E-values (VanderWeele & Ding), Rosenbaum bounds, or omitted-variable-bias bounds (Cinelli & Hazlett’s sensemakr). “How strong would a hidden confounder need to be to explain this away?”
  • Prefer doubly robust + cross-fitting when using ML models for nuisance functions.
  • Libraries: DoWhy (graph-first workflow + refutation tests), EconML (DML, causal forests, heterogeneous effects), causalml, zEpid.

5.6 Check your understanding

TipWhy judge a propensity model by balance rather than by AUC?

The model’s job is to balance covariates between the groups, not to predict treatment. A highly predictive model can mean poor overlap. Check that |SMD| falls below about 0.1 after weighting.

TipWhat does double robustness guarantee, and what doesn’t it?

AIPW is consistent if either the outcome model or the propensity model is correct. It fails when both are wrong, and it cannot fix a confounder you never measured.

    a1 = LinearRegression().fit(X_out[t == 1], y[t == 1]); a0 = LinearRegression().fit(X_out[t == 0], y[t == 0])
    return ps_lib.aipw(y, t, p, a0.predict(X_out), a1.predict(X_out)).estimate

    {"propensity model": "correct", "outcome model": "correct", "IPW": ipw_ate(X_good, y, t), "reg. adj.": regression_adjustment(X_good, y, t), "AIPW": aipw_with(X_good, X_good)},
    {"propensity model": "correct", "outcome model": "wrong", "IPW": ipw_ate(X_good, y, t), "reg. adj.": regression_adjustment(X_bad, y, t), "AIPW": aipw_with(X_good, X_bad)},

In @tbl-ps-doublerobust, leaving the key confounder out of the **propensity** model breaks IPW but not AIPW (the outcome model rescues it); leaving it out of the **outcome** model breaks regression adjustment but not AIPW (the weights rescue it). Only when *both* are wrong does AIPW fail — double robustness is protection against one mistake, not two, and no model fixes a confounder you never measured.

## Practical notes

- **Design before analysis:** write down the causal graph; include pre-treatment confounders, exclude mediators and colliders (and instruments, which inflate variance and can amplify bias).
- **Overlap first,** then balance, then estimate. Report how many units were trimmed or unmatched — it changes the population the estimate describes.
- **Sensitivity analysis** for unmeasured confounding: E-values (VanderWeele & Ding), Rosenbaum bounds, or omitted-variable-bias bounds (Cinelli & Hazlett's `sensemakr`). "How strong would a hidden confounder need to be to explain this away?"
- **Prefer doubly robust + cross-fitting** when using ML models for nuisance functions.
- **Libraries:** `DoWhy` (graph-first workflow + refutation tests), `EconML` (DML, causal forests, heterogeneous effects), `causalml`, `zEpid`.

[^smd]: SMD: standardized mean difference, the difference in group means divided by the pooled standard deviation.

## Check your understanding

::: {.callout-tip title="Why judge a propensity model by balance rather than by AUC?" collapse="true"}
The model's job is to balance covariates between the groups, not to predict treatment. A highly predictive model can mean poor overlap. Check that |SMD| falls below about 0.1 after weighting.
:::

::: {.callout-tip title="What does double robustness guarantee, and what doesn't it?" collapse="true"}
AIPW is consistent if either the outcome model or the propensity model is correct. It fails when both are wrong, and it cannot fix a confounder you never measured.
:::
